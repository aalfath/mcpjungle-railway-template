# MCPJungle on Railway

One-click Railway template for [MCPJungle](https://github.com/mcpjungle/MCPJungle) **0.4.7**, a self-hosted MCP gateway and registry: register all your MCP servers in one place and give your AI clients (Claude, Cursor, VS Code, your own agents) a single authenticated MCP endpoint.

## What it deploys

| Service | What it does |
|---|---|
| **MCPJungle** | Built from this repo: the official image `ghcr.io/mcpjungle/mcpjungle:0.4.7-stdio` (pinned by digest; includes `npx` and `uvx` for STDIO MCP servers) plus a small start script. Runs in **enterprise mode**, so every API and MCP call needs a token. Public URL, health check on `/health`, volume on `/data` for the npm/uv caches of STDIO servers. |
| **Postgres** | Railway's Postgres, on its own volume. Holds every registered server, tool, client and user. |

On first boot the start script initialises the server (what `mcpjungle init-server` does by hand), sets the admin token from `MCPJUNGLE_ADMIN_TOKEN`, and creates an MCP client named `default` whose token is `MCPJUNGLE_CLIENT_TOKEN` and which may use every registered server. Both tokens are generated by Railway for each deployment; nothing is fixed or shared.

## Variables

| Variable | Default | Notes |
|---|---|---|
| `MCPJUNGLE_ADMIN_TOKEN` | generated, 40 characters | Admin token for the REST API and the `mcpjungle` CLI (register servers, create clients and users). |
| `MCPJUNGLE_CLIENT_TOKEN` | generated, 40 characters | Bearer token your AI clients send to `/mcp`. Change it in Railway and redeploy to rotate it. |
| `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` | Reference to the Postgres service. |
| `PORT` | `8080` | Port the gateway listens on. |

There are no prompts. Optional settings you can add yourself: `OTEL_ENABLED=true` (Prometheus metrics on `/metrics`; off by default because that path is public), `MCP_SERVER_INIT_REQ_TIMEOUT_SEC` (default 90 here), `SESSION_IDLE_TIMEOUT_SEC`.

## After deploying

1. Copy `MCPJUNGLE_ADMIN_TOKEN` and `MCPJUNGLE_CLIENT_TOKEN` from the MCPJungle service's **Variables** tab.
2. Install the CLI on your machine ([releases](https://github.com/mcpjungle/MCPJungle/releases) or `brew install mcpjungle/mcpjungle/mcpjungle`) and log in:
   ```sh
   mcpjungle login YOUR-ADMIN-TOKEN --registry https://YOUR-DOMAIN.up.railway.app
   ```
3. Register MCP servers, for example a remote one and a STDIO one:
   ```sh
   mcpjungle register --name context7 --url https://mcp.context7.com/mcp
   cat > time.json <<'JSON'
   {"name": "time", "transport": "stdio", "command": "uvx", "args": ["mcp-server-time==2026.11.18"], "session_mode": "stateful"}
   JSON
   mcpjungle register -c time.json
   ```
4. Point your AI client at the gateway. Cursor / Claude Desktop style config:
   ```json
   {
     "mcpServers": {
       "mcpjungle": {
         "url": "https://YOUR-DOMAIN.up.railway.app/mcp",
         "headers": { "Authorization": "Bearer YOUR-CLIENT-TOKEN" }
       }
     }
   }
   ```
   Claude Code: `claude mcp add --transport http mcpjungle https://YOUR-DOMAIN.up.railway.app/mcp --header "Authorization: Bearer YOUR-CLIENT-TOKEN"`

Tools show up as `<server>__<tool>`. For finer access control, create more clients with `mcpjungle create mcp-client NAME --allow "server1, server2"`, and tool groups with `mcpjungle create group`.

## Notes and limits

- **Web dashboard:** upstream serves its dashboard only in development mode, which has no authentication, so this template doesn't expose it. Manage the gateway with the CLI or the REST API.
- **Memory:** the gateway uses about 20–40 MB. Each STDIO MCP server is a child process: a Node `npx` server takes about 50–60 MB, a Python `uvx` server about 70 MB (our test with two STDIO servers and one remote server used about 120 MB). Pin STDIO server versions (`pkg@1.2.3`, `pkg==1.2.3`) so a new upstream release can't break them. On Railway's Free plan (0.5 GB per service), register STDIO servers with `"session_mode": "stateful"`: in the default `stateless` mode every tool call starts a new process, and in our test 10 parallel calls to one Node server ran out of memory (the gateway itself kept running). Remote (Streamable HTTP) servers cost almost nothing.
- **No Docker:** STDIO servers that need Docker (`docker run …`) can't run on Railway. Use their `npx`/`uvx` form or a remote URL.
- **Admin token:** the admin token is stored in Postgres at first boot. If you change `MCPJUNGLE_ADMIN_TOKEN` later, rotate it first with `mcpjungle update user admin --access-token NEW` (logged in with the old token); otherwise the start script logs a warning and keeps the old one.

## Updates

This template builds from this repository. When we bump MCPJungle here, Railway shows an "update available" notice on your project and you choose when to apply it. Read [CHANGELOG.md](CHANGELOG.md) first; breaking changes are listed at the top of each entry. Your servers, clients and tokens live in Postgres and are kept across updates.
